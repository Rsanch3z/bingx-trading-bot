# 自動交易開發路線圖

## 第 1 階段：只讀與 dry-run

目標：確認程式可以穩定取得行情、產生訊號、計算倉位，但不送出真實訂單。

- 讀取 BTC/USDT 永續合約 K 線
- 用既有指標產生做多、做空、空手訊號
- 用 Kelly 公式估算倉位
- 用最大單筆風險裁切 Kelly 結果
- 記錄 dry-run 訂單到交易日誌

建議門檻：

- 至少連續 dry-run 3-7 天
- 沒有重複下單、反向下單、倉位異常
- 每筆預估風險符合設定

## 第 2 階段：模擬倉實單

目標：用 BingX 模擬倉 API 驗證真實交易流程。

- 建立模擬倉 API key
- 設定 `.env`
- 確認可以下市價單
- 確認止盈止損是否被交易所接受
- 確認成交後交易日誌能更新勝率和損益

建議門檻：

- 至少 20 筆以上完整交易紀錄
- 勝率和盈虧比合理
- 最大回撤可接受
- 交易所手續費和滑價已納入評估

## 第 3 階段：10U 小額實盤

目標：只用小額驗證真實市場行為，不追求獲利。

- `STARTING_EQUITY_USDT=10`
- `LEVERAGE=1` 起步
- `MAX_RISK_PER_TRADE_PCT=0.01` 或更低
- `MAX_DAILY_LOSS_USDT=1`
- API key 不開提幣權限
- 設定 IP 白名單

建議門檻：

- 連續 1-2 週無程式錯誤
- 沒有超額下單
- 日誌能完整追蹤每筆交易

## 第 4 階段：策略擴充

可以逐步加入：

- 你已有的指標訊號
- 多時間框架過濾
- 波動率調整止損
- 交易時段限制
- 最大連敗暫停
- Telegram / Discord 通知
- 回測模組

## 風控原則

- Kelly 只能當作上限參考，不應原樣重倉使用
- 永續合約先用 1 倍槓桿驗證流程
- 沒有完整日誌就不要加大資金
- 沒有停損就不要自動下單
- 程式任何例外都應該停止交易，而不是繼續猜
